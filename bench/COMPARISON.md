# 上下文编排运行时的三态对照实验

**——关闭插件、规则决策、外置决策模型（TypeSafe Jev）在模拟真实聊天语料上的配对比较**

*AI还没忘 v0.2.1 · 2026-10-14 · 全部脚本与原始数据可复现（附录 A）*

---

## 摘要

千楼级角色扮演对话超出一切现有模型的上下文窗口，社区通行做法是「总结替换历史」，但该做法没有回答两个问题：**压缩后的上下文供给是否仍然安全**（不越窗、不丢系统注入），以及**决策由谁做出更好**（本地规则 vs 外置决策模型）。本文在模拟真实聊天语料（100/500/2000 楼三档，中英混合 RP，含 115,432 字符的预设+世界书+卡牌 system）上，对同一插件的三个运行态做同输入配对比较：

- **B0（关闭插件）**：原始全量发送；
- **B1（开启，规则决策）**：本地规则决策 + 预算梯度压缩 + 规则记忆/摘要/召回；
- **B2（开启 + Jev）**：决策层替换为 TypeSafe Jev（System One 决策模型），其余链路不变。

主要结果：**(i)** B0 下 2000 楼 ≈ **19,991 千 token**，任何 ≤1M 窗口模型不可发送；B1/B2 将其压至 **114.8 千（0.57%）**且 **0/10 检查点越窗**、system 块 **130/130 保留、0 泄漏**。**(ii)** B1→B2 在决策层带来实质改善——55%（11/20）的楼层点意图判定不同且人工审查全部支持 B2，规则对同模板输入的判定**漂移**（同模板 4 次给出 3 种判定）而 Jev 判定一致（conf=1.0）；但在端到端输出上两者高度趋同（finalTokens 配对均差 18 tokens，result 20/20 一致），原因是压缩档一致率 95%，意图差异不直接驱动降级动作。**(iii)** Jev 的代价为 p50 228ms 延迟与 ≈2.6k tokens/轮辅助消耗（占压缩节省的 0.09%）。**(iv)** 负结果：Jev 的 noul（召回必要性）信号无区分度（0.343 vs 0.332），不可用作召回开关。

**配置建议**：保持 B2（Jev + V2 指令 + 阈值 0.4）作为决策与诊断层；意图驱动的压缩/召回策略是未来兑现增益的方向。

## 1 引言

### 1.1 问题

长对话上下文供给需要同时满足三个约束：**窗口约束**（总 token ≤ 模型窗口 − 输出预留）、**信息约束**（模型仍能拿到回答当前轮所需的事实）、**安全约束**（用户配置的预设/世界书/卡牌等系统注入必须完整且不被摘要过程污染）。社区主流方案（生成式总结）集中解决第二条，对第一、三条通常缺乏硬保障。

AI还没忘把上下文供给建模为**预算问题**（操作系统式的分层记忆管理 [2] 在应用层的落地）：每轮发送前对「发送副本」重新规划，按「最近原文 > 锚点 > 定向召回 > 章节摘要 > 合并摘要 > 截断最旧」的梯度降级，直到满足窗口；无法满足时明确阻止发送并给出修复动作，而非静默截断。

### 1.2 决策层的位置

规划器每轮需要六个判断：输入意图、记忆需求类型、压缩档位、召回必要性、冲突风险、内容重要度。v0.2.1 之前由本地规则（关键词命中 + 楼层启发式）做出；本文考察把该层替换为 TypeSafe Jev——一个以「state + 带类型问题 → 结构化答案 + 校准置信度」为接口的 System One 决策模型——是否带来可测量的收益，以及代价几何。

### 1.3 研究问题

- **RQ1**：插件能否使千楼级对话满足窗口与安全约束（B0 vs B1/B2）？
- **RQ2**：记忆/摘要/召回三条通道的信息质量如何（B1 内部分析）？
- **RQ3**：外置决策模型相对规则决策的增益与代价（B1 vs B2）？

## 2 系统机制与设计思路

本章交代被测系统的机制本身——后续实验的每一个数字都由这些机制产出。三条设计公理贯穿全局：**可解释**（每轮注入什么、为什么，全部留痕可查）、**可回滚**（快照、撤销、迁移回滚，任何写操作有退路）、**本地优先**（零第三方依赖，记忆与压缩默认不出本机；一切「可能外发」的能力默认关闭且如实标注）。

### 2.1 总体架构与数据流

```
SillyTavern 事件（消息/编辑/删除/swipe/分支）
   → 摄取 ingest（消息事件落库，带楼层/说话人/分支隔离）
   → 后台任务队列（逐轮：规则抽取 → 冲突检测 → 章节摘要；串行 + 让出事件循环）
发送前拦截器 generate_interceptor
   → 探针（模型/窗口/tool 口径/兼容插件）
   → 预算规划 plan（检索 → 决策 → 梯度降级 → 编译注入副本）
   → 应用注入与压缩 → 硬预算终检 → 发送
```

内核以 SillyTavern [9] 服务端插件形态随酒馆进程运行（零第三方依赖，Node 内置 `node:sqlite`，低于 22.13 自动降级 append-only journal 存储）；浏览器扩展只做 UI 与拦截。压缩只作用于「发送副本」，聊天原文永不改动。

### 2.2 记忆机制：生命周期与置信度

自动记忆有完整的生命周期：`candidate → observed → confirmed → active`（+ 归档/墓碑），与记忆智能体中「记忆流 + 检索」的通用架构 [4] 相比增加了状态机与置信度门控。设计思路是**「先观察，后信任」**：

- 观察期（`shadowMode: 'first-n'`）：新会话前 N 轮抽取的事实只记不注入，防止冷启动洪泛；
- 晋升需要置信度门槛（0.55）：用户消息来源加分、助手消息来源降权（避免模型幻觉当事实）；
- 冲突检测按实体词典定主语：同名主语出现矛盾值（改名、换剑）触发 `conflict` 记录与纠正阻断，而不是两说并存；
- 遗忘/彻底删除带墓碑与 epoch，防止旧快照恢复把删掉的记忆带回来。

抽取规则覆盖 6 类候选（事实/状态变化/时间信号/关系转折/反转/情感转折）——不依赖 LLM 重写，因此不存在 MemoryBank 式生成记忆 [3] 的幻觉风险与调用成本，其中 `emotion-shift` 规则专门捞「靠神态动作暗示的关系变化」——这类信号没有显式措辞，纯关键词方案必然漏。

### 2.3 摘要机制：逐句摘录而非生成

章节摘要**不生成新文本**，而是从原文里「选句」：每章按打分挑选代表性句子拼接，打分 = 词频 + 词汇稀有度（IDF，全章只出现一两次的词如「玉佩」「断口」权重远高于人名口头禅）+ 新颖度（与全章最相似句越不像加分越多）− 模板簇惩罚（同句式换词的填充句降权）+ 叙事线索词加成。选择计算有界（粗排池 ≤240 × 整章参照集 ≤600），长章节不再阻塞事件循环。

选句式摘要属于**提取式压缩**——与 LLMLingua 的提示压缩 [1] 同属「不重写原文」的路线，区别在于 LLMLingua 按 perplexity 删词，本插件按可解释信号选句。选句式摘要的两个刻意取舍：**可审计**（摘要每个字都来自原文，可回放验证）与**零生成成本**；代价是概括能力弱于 LLM 生成式总结（见附录 B 定位差异）。

### 2.4 检索机制：BM25 分集合配额

定向召回以 BM25 [7] 在两个集合上检索——记忆条（`memory_records`）与原始消息事件（`message_events`）。关键机制是**按集合分别取配额、分别归一化分数**：整章长文（数千词）的 BM25 累计分天然比几十字记忆条高一两个数量级，合并排序会让原始消息全额占据候选、再把记忆挤出局。召回正例命中率 1.2% → 24.1% 的修复即来源于此。检索式召回相对「全量历史塞入」的收益已有成熟结论 [6]；而长上下文并非无敌——「Lost in the Middle」表明模型对窗口中部信息的利用率显著下降 [5]，这解释了为什么把 2 万 token 的历史**原样**塞进 1M 窗口并不是压缩的合理替代。召回块另带保底配额（`recallFloorRatio` 按档位 0.06/0.04/0.02）：预算再紧张也先保一段召回，其余从最低分丢起。

### 2.5 压缩机制：预算梯度而非一次性截断

规划器每轮把注入内容组装成带保护的块序列，按「**最近原文 > 用户锚点 > 定向召回 > 章节摘要 > 合并摘要 > 截断最旧**」的梯度降级：

- 触发分两级：**档位触发线**（balanced 0.75，超过即开始轻量降级，避免贴脸截断）与**硬预算**（availableInput，最终兜底）；
- 系统注入（预设/世界书/卡牌）标记 `protected`、不可丢弃不可摘要化，纯系统章节整体跳过摘要；
- 无法满足硬预算时**阻止发送**并给出修复动作（缩小窗口/精简预设），绝不静默丢系统块——「发送一个残缺的上下文」比「不发送」更危险；
- 每轮计划完整落库：注入了什么、丢了什么、为什么、省多少，面板可查可回滚。

### 2.6 决策层：规则优先，模型可选

六个逐轮判断（意图/记忆需求/压缩档/召回必要性/冲突风险/重要度）默认由本地规则给出；可选替换为 TypeSafe Jev [8]（System One 决策模型，一次请求并行六问，返回带校准置信度的结构化答案）。路由策略是**防御性的**：schema 校验失败、置信度不足、超时、429、连续失败 3 次自动停用——任一异常都回退规则计划并记录原因，决策层故障不阻断发送。决策结果连同理由写入计划留痕，供面板展示与本实验测量。


## 3 实验设计

### 3.1 语料与环境

| 项 | 值 |
|---|---|
| 语料 | 模拟真实聊天语料三档：L1-100 / L2-500 / L3-2000 楼，中英混合 RP |
| system 注入 | 取自语料中单会话最大的一次真实请求：130 条消息、115,432 字符（预设+世界书+卡牌） |
| 运行环境 | Node 22.x，`node:sqlite` WAL，隔离实例离线回放 |
| 插件配置 | 档位 balanced；观察期结束后进入稳态口径（自动晋升全部候选记忆）；token 口径为插件保守估算（实测对 Gemini 系中文高估 1.64~1.88×，见 §6） |

### 3.2 配对设计与变量控制

- **E12（决策层，N=40）**：均匀采样 40 条真实用户消息，每条构造「当前消息 + 前 4 楼窗口 + 真实累计预算」，B1 规则 / B2-JevV1 / B2-JevV2 三组同输入；V1 前 10 条复测定稳定性。
- **E13（端到端，N=20 楼层点）**：稳态语料上取 20 个楼层点，每点构造「截至该楼层的完整对话 + 该消息为 userInput」的完整 planRequest，B1/B2 各跑一遍。**两批之间重建决策路由**以隔离 DecisionCache（否则后跑批次命中前批缓存，构成混杂）。
- B2 统一使用 V2 指令（精调版）与阈值 0.4（V1/V2 的选择依据见 §4.3 来源与口径）。

### 3.3 指标定义

- **finalTokens**：规划后发送副本的 token 估算；**越窗** = finalTokens > availableInput 且未阻止。
- **召回命中**：以「含跨章关键实体（出现 ≥3 次、首末跨度 ≥60 楼、过滤噪声词）的历史用户消息」为正例查询，命中 = 召回项文本含该实体；负例 = 不含该实体的确定性随机提问。
- **system 泄漏**：system 消息片段出现在章节摘要文本中。
- **决策漂移**：同一（模板）输入在不同楼层点的判定离散度。

## 4 结果 I：窗口与安全约束（RQ1，B0 vs B1/B2）

### 4.1 上下文规模

| 楼数 | B0 全量 token | B1/B2 @128k 档 | B1/B2 @1M 档 |
|---|---|---|---|
| 100 | ≈1,376 千 | ≈115 千（system 主导） | ≈115 千 |
| 500 | ≈4,998 千 | **114.8 千**（实测） | ≈600 千 |
| 2000 | **19,991 千**（实测） | **114.8 千**（实测，0.57%） | **651.9 千**（实测，3.25%） |

B0 的规模随楼数线性增长；B1/B2 被 system 体积（97k token）与窗口预算钳制在一条近水平线上。**B0 在任何 ≤1M 窗口模型上不可发送**（2000 楼为 1M 窗口的 20 倍）；B1/B2 在 128k/1M 档全部可发送。

## 5 结果 II：信息通道质量（RQ2，B1）

### 5.1 记忆与摘要通道（500 楼，3,041 条自动记忆）

| 通道 | 关键实体覆盖 | 说明 |
|---|---|---|
| 自动记忆（规则抽取） | 58.9~71.4% | 逐字摘录，含 emotion-shift 规则（275 条/500 楼） |
| 章节摘要（逐句摘录） | 18.4~25.8% | 摘要总量极小（0.036~0.045%），定位是叙事骨架 |
| **两通道并集** | **62.1~73.2%** | 2000 楼档 50.0%（规模效应：每楼均摊 3.6 条） |
| 伏笔埋点存活（3000 楼 8 埋点） | **8/8** | 词汇稀有度（IDF）+ 新颖度打分 |

记忆维护**零 LLM 生成**：抽取与摘录全部本地完成，这是与生成式总结方案的本质成本差异。

### 5.2 定向召回（修复 D35 后，500 楼）

| 指标 | 数值 |
|---|---|
| 正例命中（含跨章实体的历史提问，N=83） | **24.1%** |
| 负例误命中（随机提问） | 7.2% |
| 随机基线（命中率若与实体无关） | 8.6% |
| 平均召回条数 | 4.1 |

正相关成立（2.8 倍于基线）但绝对值不高：**整章粘贴式输入没有单一「当前话题」**，实测截断查询无益（全文/末1000/末400 = 21.0/18.1/16.9%）。关键情节连续性主要由记忆条 + 章节摘要两通道承担。

### 5.3 预算紧张时的召回保障（D31 修复验证）

131k/1M 档 × 三档语料下，召回存活严格分层：**保真 16 / 均衡 10 / 节省 6 条**（修复前恒为 0）——降级梯先保召回配额再按分丢弃。

## 6 结果 III：决策层对照（RQ3，B1 vs B2）

### 6.1 意图判断质量（E12，N=40）

| intent | B1 规则 | B2 Jev-V2 |
|---|---|---|
| roleplay | 17 | **32** |
| summary | **15** | 0 |
| status | 2 | 7 |
| question | 4 | 0 |
| smalltalk | 0 | 1 |

规则的 15 个 summary 集中在两类系统性误判：**英文 RP 叙事**与**系统注入消息**（预设模板、状态栏指令、历史存档标注）。更严重的是**判定漂移**：同一英文模板句在 4 个楼层点被规则判为 combat / status / summary / combat（3 种结果），而 Jev 四次全部判 roleplay（conf=1.0）——规则的楼层启发式随上下文比例变化而摆动，Jev 的判定对输入本身稳定。

E13 端到端的 20 个楼层点中 **11 个（55%）意图不同**，逐点人工审查（含设定修正块、历史存档块、状态栏指令、英文叙事）全部支持 B2。

### 6.2 端到端输出：决策增益为何没有传导（E13）

| 指标 | B1 规则 | B2 Jev | 配对差异 |
|---|---|---|---|
| result | ok 1 / degraded 19 | ok 1 / degraded 19 | **20/20 一致** |
| finalTokens 均值 | 114,875 | 114,887 | **±18 tokens** |
| savedTokens 均值 | 2,744,221 | 2,744,209 | −12 |
| 召回注入均值 | 8.90 条 | 8.85 条 | −0.05 |
| 压缩档一致 | — | — | **95%** |

**机制分析**：意图差异之所以不传导到输出，有两条路径原因——(1) 压缩档（唯一直接改变降级行为的决策字段）两层一致率 95%，唯一分歧点是楼层 130（规则 normal，Jev none——Jev 正确识别该轮为 smalltalk 过渡，无需压缩）；(2) 意图与 memoryNeeds 当前只写入计划的可解释字段与面板展示，**不参与预算计算**。换言之，B2 买到的不是「压得更狠」，而是**更可信的决策记录**（每轮可审计的意图/风险/重要度）与一个尚未启用的增益通道：intent 驱动策略（combat 轮保召回、question 轮放宽压缩）一旦接通，55% 的判定差异即可转化为行为差异。

### 6.3 置信度校准与阈值（V1 vs V2）

B2 confidence 分布（N=40）：0-20%: 0 | 20-40%: 1 | 40-60%: 3 | 60-80%: 11 | **80-100%: 25**。清晰 RP 输入 1.0；边界输入（系统注入、状态栏）0.46~0.89——校准方向正确（越明确越自信）。

![置信度阈值扫描](bench/chart-threshold.svg)

V1/V2 的采用率曲线在 0.4 处几乎重合（97.5%），0.6 以上分离（V1 87.5% vs V2 90%）。**推荐阈值 0.4**：拦下的 2.5% 恰是需要回退规则的低置信边界决策；更严的阈值把 10~17.5% 的正常决策一并回退，无质量证据支持。**推荐 V2 指令**：边界情形处理更好（历史存档块判 none 而非 normal），且 ≥0.6 档采用率始终更高。同输入重复调用 **10/10 完全一致**。

### 6.4 成本

| 项 | B1 | B2 |
|---|---|---|
| 决策延迟 p50 / p90 | ~0（本地） | **228 / 257 ms** |
| 辅助 token / 轮 | 0 | ≈2,378 input + 228 output |
| 占单轮压缩节省 | — | **0.09%**（2.6k / 2,744k） |
| plan 总耗时 | 1,083 ms | 2,101 ms（p90 3,313 vs 1,843） |

### 6.5 负结果：noul 不可用

| 条件 | 应召回组均值 | 无关组均值 |
|---|---|---|
| state 无候选（N=15/25） | 0.335 | 0.330 |
| state 喂召回候选（N=12/12） | 0.343 | 0.332 |

noul≥0.5 作门槛 precision 0.5 / recall 0.133，近随机。机制：noul 对问题**孤立评估**，而召回必要性是「历史内容 × 当前依赖」的联合判断；且「消息提到旧实体」≠「回复依赖它」。现网影响面：noul 仅控制 `canDropIds` 边缘分叉，召回主通道由检索打分与保底配额驱动，不受影响。

## 7 效度威胁

1. **token 口径**：插件估算对 Gemini 系中文高估 1.64~1.88×（p50 1.843），保守方向 100% 成立——压缩量被系统性高估，但三态对照为**同口径配对比较**，差异不受影响；绝对值应按此系数解读。
2. **意图无全量标注**：「更准确」基于 19 个分歧样例（E12 8 个 + E13 11 个）的人工审查，非盲评。
3. **单语料家族**：三档语料同源，跨风格（纯中文长篇、跑团）泛化未验证。
4. **E13 的预算环境**：131k 档下 system 占预算 83%，压缩行为以 aggressive 为主（19/20），压缩档多样性受限；1M 档分布可能不同。
5. **Jev 模型版本**：jev-1.13.0，模型升级可能改变校准曲线，阈值 0.4 需随版本复核。

---

## 8 结论与定位

1. **RQ1 成立**：B0 不可用（20M token / 1M 窗口 = 20 倍超窗）；B1/B2 在 128k/1M 档全部可发送，0 越窗、0 静默截断、system 130/130 保留零泄漏。
2. **RQ2**：零 LLM 生成成本下，记忆两通道覆盖 62~73%、埋点 8/8、召回 2.8 倍于随机基线；召回上限是整章输入的本质限制（截断无益）。
3. **RQ3**：B2 的增益集中在**意图判定质量与判定稳定性**（55% 楼层点不同、消除了规则的模板漂移），端到端输出暂与 B1 趋同（差 18 tokens）；代价 p50 228ms + 0.09% 净收益损耗。
4. **建议配置**：B2 = 开启插件 + TypeSafe Jev（`jev-latest`、V2 指令、阈值 0.4）。意图驱动的压缩/召回策略是把 55% 判定差异转化为行为差异的下一阶段工作。
5. **已知限制**：LLM 概括能力弱于生成式总结方案；2000 楼峰值内存 2.6 GB；≤32k 窗口 + 大体积预设组合无法使用压缩（由 system 体积决定，属模型约束）。

## 附录 B：与生成式总结方案的定位差异

本插件不依赖 LLM 生成记忆（规则抽取 + 逐句摘录，零生成成本、可回放审计），因此**不与「生成式记忆/总结类」方案直接互斥**：后者的叙事概括能力更强，本插件强在硬预算保障、系统块保护与决策可审计。二者可共存（本插件兼容从常见总结/记忆插件迁移导入）。
